`styles/globals.css` lines 92 to 102 define a `[data-contrast="high"]` attribute, set by `providers/AccessibilityProvider.tsx` from Settings, that raises `--rule`, `--rule-strong` and `--ink-muted` beyond their default values, with separate values for Day and Night. This sits on top of the base tokens above; it does not replace them.

**Border selection rule.** Decorative separation (`--rule`) is not verified to 3:1 and is not meant to be; it is a low-contrast divider, not an interactive boundary. Form input borders use `--rule-strong` specifically because WCAG 1.4.11 (Non-text Contrast) requires 3:1 for interactive component boundaries, and `--rule-strong` clears that bar (3.02:1 Day, 3.30:1 Night) while `--rule` does not.

**Text selection rule.** Placeholder and muted text use `--ink-muted`, which clears the 4.5:1 body-text threshold in both themes, rather than a lower-contrast token.

## Clinical risk matrix and shape indicators

Colour is never the only signal. Every risk indicator ships a drawn Lucide shape, a text label, and a colour together. Emoji are not used as icons anywhere in the shipped risk display.

Source: `components/ui/RiskIndicator.tsx`, `RISK_CONFIG` (lines 29 to 34), which is the single source of truth for risk display in the app.

| Level | Text / solid token | Lucide icon (exact import name) | Label rendered |
| --- | --- | --- | --- |
| Emergency | `--risk-emergency` | `Octagon` | "Emergency" |
| High | `--risk-high` | `Triangle` | "High risk" |
| Moderate | `--risk-moderate` | `Circle` | "Moderate" |
| Low | `--risk-low` | `Shield` | "Low risk" |

All four icons are imported from `lucide-react` and rendered at a fixed `strokeWidth={1.75}`, `h-4 w-4`, `aria-hidden="true"`, with the accessible name carried instead by the component's own `aria-label={\`Assessed risk level: ${label}\`}` on the wrapping `<span>`.

`RiskIndicator` ships three variants, each with its own Tailwind color classes built from the `risk` token family exposed in `tailwind.config.js` (`bg-risk-emergency`, `text-risk-emergency`, and so on):

| Variant | Rendering |
| --- | --- |
| `solid` | Solid `bg-risk-*` fill with `text-on-action` ink, in a `rounded-chip` pill |
| `tint` (default) | `bg-risk-*/12` tinted fill with `text-risk-*` ink, in a `rounded-chip` pill |
| `inline` | No pill background at all, just `text-risk-*` on the icon and label |

`RiskIndicator` also accepts an optional `showScore` number (0 to 10), rendered through the `Data` typography component with tabular figures.

Vital status maps onto the same four-level scale: `alert` maps to Emergency, `warning` maps to High, `normal` maps to Low. This mapping is documented in the design spec (`docs/superpowers/specs/2026-08-28-medigem-surgical-ui-design.md`, section 4.3) and is consistent with the shipped `RiskLevel` type.

## Action color and clinical semantics stay separate

Deep indigo (`--action` and its states) is the sole action/brand color. It is never used to signal clinical severity. Red, amber and green (the four `--risk-*` tokens) are reserved exclusively for clinical meaning and never used for navigation, branding, or non-clinical UI state. This separation is enforced by keeping the two token families (`action`, `risk`) distinct in `tailwind.config.js` rather than sharing hues, and by `RiskIndicator` being the only place risk color is produced.
